# ผลการทดสอบประสิทธิภาพและการรองรับโหลด

เอกสารนี้แสดงผลการทดสอบจริง (Empirical Benchmark) ด้านขีดความสามารถ (Capacity), อัตราการรับส่งข้อมูล (Throughput) และการใช้ทรัพยากรระบบของ `@raina-iot/rlp` บน Node.js

---

## สภาพแวดล้อมในการทดสอบ

- **เครื่องเซิร์ฟเวอร์:** Apple Silicon (macOS arm64, 8 Logical Cores, RAM 16 GiB)
- **รันไทม์:** Node.js v24.18.0
- **รูปแบบการทดสอบ:** รันบนเครื่องเดียวกันผ่าน Localhost ด้วย Plain TCP
- **ระเบียบวิธี:** ฝั่ง RLP Server รันใน Child Process และตัวสร้างโหลด (Fleet Generator) รันใน Parent Process โดยทั้งสองโปรเซสบันทึกค่า RSS, การใช้ Heap, ปริมาณการใช้ CPU และค่าความหน่วงของ Event Loop แยกจากกันทุก ๆ 1 วินาที

---

## 1. การไต่ระดับจำนวนการเชื่อมต่อ (Connection Ramp)

ข้อมูลการวัดการใช้ทรัพยากรระหว่างที่จำนวนการเชื่อมต่อเพิ่มขึ้น:

| จำนวนอุปกรณ์ที่เชื่อมต่อ | Server RSS | Server Heap ที่ใช้งาน | Event Loop p99 | จำนวนการหลุด |
|---:|---:|---:|---:|---:|
| **1,000** | 73.6 MiB | 9.1 MiB | 2.29 ms | 0 |
| **5,000** | 99.3 MiB | 26.3 MiB | 1.21 ms | 0 |
| **10,000** | 121.7 MiB | 32.0 MiB | 1.23 ms | 0 |

---

## 2. การทดสอบส่ง Telemetry ต่อเนื่อง 10 นาที (10k Devices)

การทดสอบยืนยันผลการทำงานต่อเนื่องเป็นเวลา 10 นาที โดยมีอุปกรณ์เชื่อมต่อและยืนยันสิทธิ์สำเร็จคงที่อยู่ที่ 10,000 อุปกรณ์ และส่งข้อมูลเซนเซอร์ทุก 5 วินาที:

| สถานการณ์ทดสอบ | จำนวนการเชื่อมต่อ | อัตราการส่ง | ระยะเวลา | Server RSS | Event Loop p99 | ผลลัพธ์ |
|---|---:|---:|---:|---:|---:|---|
| **Environmental Telemetry** | 10,000 | 1,994.85 ข้อความ/วิ | 10 นาที | 90.8 MiB | 1.99 ms | **ผ่าน (PASS)** |

### ข้อสังเกตสำคัญจากการทดสอบ

* **ไม่มีข้อมูลสูญหาย:** ตัวจำลองส่งเฟรมออกไปทั้งสิ้น `1,192,918` เฟรม และเซิร์ฟเวอร์ได้รับ `1,192,823` เฟรม (ส่วนต่าง 95 เฟรมคือข้อมูลที่อยู่ระหว่างส่งผ่านเครือข่ายขณะตัดรอบ Snapshot)
* **ปราศจากข้อผิดพลาด 100%:** อัตราการหลุดกะทันหันเป็น 0, ไม่พบ Protocol Error, ไม่พบ Client Error และไม่เกิดสภาวะ Backpressure บน Socket
* **ใช้ CPU ต่ำมาก:** เซิร์ฟเวอร์ใช้ CPU เฉลี่ยเพียง **8.48% ของ 1 CPU Core** (รวมทั้ง User และ System Process Time)
* **ความหน่วงของ Event Loop ต่ำมาก:**
  * มัธยฐาน (p50): **1.29 ms**
  * เปอร์เซ็นไทล์ที่ 95 (p95): **1.52 ms**
  * เปอร์เซ็นไทล์ที่ 99 (p99): **1.99 ms**
* **ขนาดหน่วยความจำกะทัดรัด:** V8 Heap ที่เซิร์ฟเวอร์ใช้งานอยู่ที่ **30.6 MiB** (จาก Heap รวม 32.6 MiB) และค่า Process RSS ทั้งหมดอยู่ที่ **90.8 MiB**

---

## 3. ประสิทธิภาพการสั่งคำสั่ง (Command & ACK)

การทดสอบส่งคำสั่งไปยัง 1,000 อุปกรณ์ ด้วยอัตราเร็ว 1,000 คำสั่ง/วินาที เป็นเวลา 15 วินาที:
* เซิร์ฟเวอร์ส่งคำสั่งและได้รับ ACK ยืนยันกลับมาครบ **11,225 คำสั่ง**
* **การกระจายตัวของ Latency ในการรับ ACK:**
  * p50: **0.153 ms**
  * p95: **0.786 ms**
  * p99: **1.567 ms**
* ไม่พบคำสั่งตกค้าง ไม่เกิด Backpressure และไม่มีอุปกรณ์หลุดจากการเชื่อมต่อ

---

## 4. ความทนทานต่อข้อมูลที่ถูกแบ่งท่อน (Stream Fragmentation)

ทดสอบความทนทานของ FrameDecoder ต่อข้อมูล TCP ที่ถูกหั่นเป็นชิ้นเล็ก:
* **สุ่มตัดข้อมูลเป็นท่อน 1–64 ไบต์:** ทดสอบกับ 1,000 อุปกรณ์เป็นเวลา 15 วินาที ผลปรากฏว่าไม่มี Error เกิดขึ้น และถอดรหัสข้อมูลได้ครบ 100%
* **ส่งข้อมูลทีละ 1 ไบต์ (Byte-at-a-Time):** ทดสอบกับ 100 อุปกรณ์ ส่งข้อมูลทีละ 1 ไบต์เป็นเวลา 15 วินาที ไม่มี Error เกิดขึ้นเช่นกัน

---

## 5. บทสรุปและขีดจำกัด

ผลการทดสอบนี้ยืนยันขีดความสามารถขั้นต่ำที่วัดได้จริง (Measured Lower Bound): โปรเซส Node.js เดียวที่ใช้งาน `@raina-iot/rlp` สามารถรองรับ **10,000 อุปกรณ์พร้อมกัน** ที่ปริมาณข้อมูล **2,000 ข้อความ/วินาที** ได้อย่างมีเสถียรภาพ โดยกิน **RAM ไม่ถึง 100 MiB** และใช้ **CPU ไม่ถึง 10% ของ 1 Core**

> **หมายเหตุ:** เมื่อทดสอบเร่งจำนวนการเชื่อมต่อไปที่ 25,000 อุปกรณ์บนเครื่องเดียวกัน ระบบปฏิบัติการเกิดข้อผิดพลาด Ephemeral Port หมด (`EADDRNOTAVAIL`) ในฝั่ง Generator ก่อนที่เซิร์ฟเวอร์จะรับโหลดไม่ไหว
