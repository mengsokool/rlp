# ตัวอย่างเฟรมระดับไบต์และ Hex Dumps

เอกสารนี้แสดงตัวอย่าง Hex Dump ระดับไบต์จริงของแพ็กเก็ตทุกชนิดใน RLP Version 1 ซึ่งผ่านการตรวจสอบความถูกต้องโดยตรงกับ Encoder และ Decoder อ้างอิง

---

## 1. เฟรม HELLO (Type 1)

Client ขอเชื่อมต่อด้วย Protocol Version `1`, Device ID `"d1"`, Credential `"k"` และ Capabilities ว่างเปล่า:

```text
01 00 00 09 01 02 64 31 00 01 6b 00 00
```

### การแจกแจงโครงสร้าง (รวม 13 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `01` | Frame Type | `HELLO` (1) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 09` | Payload Length | 9 ไบต์ |
| `04` | `01` | Version | `1` |
| `05–07` | `02 64 31` | Device ID (`lp8`) | ยาว 2 ไบต์, `"d1"` |
| `08–10` | `00 01 6b` | Credential (`lp16`) | ยาว 1 ไบต์, `"k"` |
| `11–12` | `00 00` | Capabilities (`lp16`)| ยาว 0 ไบต์ |

---

## 2. เฟรม WELCOME (Type 2)

เซิร์ฟเวอร์ตอบรับการยืนยันสิทธิ์ด้วย Protocol Version `1` และ Capabilities ว่างเปล่า:

```text
02 00 00 03 01 00 00
```

### การแจกแจงโครงสร้าง (รวม 7 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `02` | Frame Type | `WELCOME` (2) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 03` | Payload Length | 3 ไบต์ |
| `04` | `01` | Version | `1` |
| `05–06` | `00 00` | Capabilities (`lp16`)| ยาว 0 ไบต์ |

---

## 3. เฟรม DATA (ไม่มี Timestamp)

Client ส่งค่าบูลีน `true` บน Channel `4`:

```text
03 00 00 04 00 04 01 01
```

### การแจกแจงโครงสร้าง (รวม 8 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `03` | Frame Type | `DATA` (3) |
| `01` | `00` | Flags | `0` (ไม่มี Timestamp) |
| `02–03` | `00 04` | Payload Length | 4 ไบต์ |
| `04–05` | `00 04` | Channel (`u16be`) | ช่องสัญญาณหมายเลข `4` |
| `06` | `01` | Value Type | `BOOL` (1) |
| `07` | `01` | Value | `true` |

---

## 4. เฟรม DATA (มี Timestamp)

Client ส่งเลขทศนิยมเดี่ยว `21.5` บน Channel `4` พร้อม Timestamp Unix `123` มิลลิวินาที:

```text
03 01 00 0f 00 04 0a 00 00 00 00 00 00 00 7b 41 ac 00 00
```

### การแจกแจงโครงสร้าง (รวม 19 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `03` | Frame Type | `DATA` (3) |
| `01` | `01` | Flags | `HAS_TIMESTAMP` (บิต 0 = 1) |
| `02–03` | `00 0f` | Payload Length | 15 ไบต์ |
| `04–05` | `00 04` | Channel (`u16be`) | ช่องสัญญาณหมายเลข `4` |
| `06` | `0a` | Value Type | `FLOAT32` (10) |
| `07–14` | `00 00 00 00 00 00 00 7b` | Timestamp (`i64be`)| `123` ms |
| `15–18` | `41 ac 00 00` | Value (`float32be`) | `21.5` |

## 5. เฟรม BATCH (Type 4)

Client ส่งข้อมูล 2 เรคคอร์ดในเฟรมเดียว (เรคคอร์ด 1: Channel 0, false; เรคคอร์ด 2: Channel 2, true):

```text
04 00 00 0c 00 02 00 00 00 01 00 00 00 02 01 01
```

### การแจกแจงโครงสร้าง (รวม 16 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `04` | Frame Type | `BATCH` (4) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 0c` | Payload Length | 12 ไบต์ |
| `04–05` | `00 02` | Count (`u16be`) | 2 เรคคอร์ด |
| `06` | `00` | Rec 1: Flags | `0` |
| `07–08` | `00 00` | Rec 1: Channel | Channel `0` |
| `09` | `01` | Rec 1: Value Type | `BOOL` (1) |
| `10` | `00` | Rec 1: Value | `false` |
| `11` | `00` | Rec 2: Flags | `0` |
| `12–13` | `00 02` | Rec 2: Channel | Channel `2` |
| `14` | `01` | Rec 2: Value Type | `BOOL` (1) |
| `15` | `01` | Rec 2: Value | `true` |

## 6. เฟรม COMMAND (Type 5)

เซิร์ฟเวอร์ส่งคำสั่งไปยัง Channel `4` ด้วยรหัสคำสั่ง `42` (`0x0000002A`) และค่าบูลีน `true`:

```text
05 00 00 08 00 00 00 2a 00 04 01 01
```

### การแจกแจงโครงสร้าง (รวม 12 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `05` | Frame Type | `COMMAND` (5) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 08` | Payload Length | 8 ไบต์ |
| `04–07` | `00 00 00 2a` | Command ID (`u32be`)| `42` |
| `08–09` | `00 04` | Channel (`u16be`) | Channel `4` |
| `10` | `01` | Value Type | `BOOL` (1) |
| `11` | `01` | Value | `true` |

## 7. เฟรม ACK (Type 6)

Client ตอบรับคำสั่งหมายเลข `42` ด้วยสถานะ `OK` (0):

```text
06 00 00 05 00 00 00 2a 00
```

### การแจกแจงโครงสร้าง (รวม 9 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `06` | Frame Type | `ACK` (6) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 05` | Payload Length | 5 ไบต์ |
| `04–07` | `00 00 00 2a` | Command ID (`u32be`)| `42` |
| `08` | `00` | Status (`u8`) | `OK` (0) |

---

## 8. เฟรม PING และ PONG (Type 7 และ 8)

ส่ง Ping ด้วย Nonce `0x12345678`:

```text
07 00 00 04 12 34 56 78
```

ฝั่งตรงข้ามตอบกลับด้วยค่า Nonce เดิมในเฟรม PONG (Type 8):

```text
08 00 00 04 12 34 56 78
```

---

## 9. เฟรม ERROR (Type 9)

เซิร์ฟเวอร์ตัดการเชื่อมต่อเนื่องจากยืนยันสิทธิ์ไม่ผ่าน `AUTH_FAILED` (รหัส 2) พร้อมข้อความ `"failed"`:

```text
09 00 00 09 00 02 06 66 61 69 6c 65 64
```

### การแจกแจงโครงสร้าง (รวม 13 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `09` | Frame Type | `ERROR` (9) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 09` | Payload Length | 9 ไบต์ |
| `04–05` | `00 02` | Error Code (`u16be`)| `AUTH_FAILED` (2) |
| `06` | `06` | Message Length (`u8`)| 6 ไบต์ |
| `07–12` | `66 61 69 6c 65 64` | Message (`UTF-8`)| `"failed"` |

### การแจกแจงโครงสร้าง (รวม 6 ไบต์)

| ไบต์ Offset | ค่า Hex | ชื่อฟิลด์ | ค่าที่ถอดรหัสได้ |
|---|---|---|---|
| `00` | `0a` | Frame Type | `DISCONNECT` (10) |
| `01` | `00` | Flags | `0` |
| `02–03` | `00 02` | Payload Length | 2 ไบต์ |
| `04–05` | `00 00` | Code (`u16be`) | `0` |
