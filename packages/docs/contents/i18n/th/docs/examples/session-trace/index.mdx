# ลำดับการทำงานตลอดทั้ง Session

เอกสารนี้แสดงการจำลองลำดับขั้นตอนการทำงานจริงตลอดทั้ง Session ของ RLP Version 1 แสดงการแลกเปลี่ยนแพ็กเก็ต การเปลี่ยนสถานะ และข้อมูลไบต์ทั้งหมดระหว่างอุปกรณ์ IoT กับแอปพลิเคชันเซิร์ฟเวอร์

---

## แผนผังลำดับขั้นตอน (Sequence Diagram)

```
Client (อุปกรณ์ "sensor-1")                              Application Server
          │                                                       │
          │──────────── 1. เชื่อมต่อ TCP สำเร็จ ──────────────────>│ [WAITING_HELLO]
          │                                                       │
          │──────────── 2. HELLO (v1, "sensor-1") ───────────────>│
          │                                                       │ [ตรวจสอบสิทธิ์]
          │<─────────── 3. WELCOME (v1) ──────────────────────────│ [สถานะ: ACTIVE]
          │                                                       │
          │──────────── 4. DATA (Ch 10, UINT16: 450) ────────────>│ ส่งต่อค่า Telemetry
          │                                                       │
          │<─────────── 5. COMMAND (ID 1, Ch 2, BOOL: true) ──────│ ส่งคำสั่งควบคุม
          │                                                       │
          │──────────── 6. ACK (ID 1, สถานะ: OK) ─────────────────>│ บันทึกผลการทำงาน
          │                                                       │
          │──────────── 7. PING (Nonce: 0xCAFEBABE) ─────────────>│
          │<─────────── 8. PONG (Nonce: 0xCAFEBABE) ─────────────│
          │                                                       │
          │──────────── 9. DISCONNECT (Code: 0) ─────────────────>│ ปิด Stream
          │<─────────── 10. ตัดการเชื่อมต่อสมบูรณ์ ────────────────│ [สถานะ: CLOSED]
```

---

## รายละเอียดแต่ละขั้นตอนและข้อมูลระดับไบต์

### ขั้นตอนที่ 1: การเปิดการเชื่อมต่อ Transport
- Client เปิด TCP Socket ไปยังพอร์ต `9000` ของเซิร์ฟเวอร์
- เซิร์ฟเวอร์เตรียม Connection ขึ้นมา กำหนดสถานะเป็น `WAITING_HELLO` และเริ่มนับเวลา Handshake Timer (10 วินาที)

---

### ขั้นตอนที่ 2: Client ส่งแพ็กเก็ต HELLO

Client เริ่มต้น Handshake โดยระบุตนเองว่าเป็น `"sensor-1"` และใช้ Credential คือ `"ok"`:

```text
01 00 00 10 01 08 73 65 6e 73 6f 72 2d 31 00 02 6f 6b 00 00
```

* **Header (4 ไบต์):** Type `01` (`HELLO`), Flags `00`, Length `00 10` (16 ไบต์)
* **Payload (16 ไบต์):**
  * Version: `01` (`1`)
  * Device ID (`lp8`): `08 73 65 6e 73 6f 72 2d 31` (ความยาว 8, ข้อความ `"sensor-1"`)
  * Credential (`lp16`): `00 02 6f 6b` (ความยาว 2, ข้อความ `"ok"`)
  * Capabilities (`lp16`): `00 00` (ความยาว 0)

---

### ขั้นตอนที่ 3: เซิร์ฟเวอร์ตรวจสอบและตอบรับด้วย WELCOME

เซิร์ฟเวอร์ตรวจสอบแล้วพบว่า Protocol Version ตรงกัน และ Credential ถูกต้อง:
- ยกเลิกตัวนับเวลา Handshake Timer
- ปรับสถานะเป็น `AUTHENTICATED` ส่งแพ็กเก็ต `WELCOME` แล้วเปลี่ยนสถานะเป็น `ACTIVE`

```text
02 00 00 03 01 00 00
```

* **Header (4 ไบต์):** Type `02` (`WELCOME`), Flags `00`, Length `00 03` (3 ไบต์)
* **Payload (3 ไบต์):**
  * Version: `01` (`1`)
  * Capabilities (`lp16`): `00 00` (ความยาว 0)

---

### ขั้นตอนที่ 4: Client ส่งข้อมูลเซนเซอร์ DATA

อุปกรณ์ส่งค่าตัวเลขจำนวนเต็มแบบไม่มีเครื่องหมาย `450` (`0x01C2`) บนช่องสัญญาณหมายเลข `10` (`0x000A`):

```text
03 00 00 05 00 0a 05 01 c2
```

* **Header (4 ไบต์):** Type `03` (`DATA`), Flags `00` (ไม่มี Timestamp), Length `00 05` (5 ไบต์)
* **Payload (5 ไบต์):**
  * Channel: `00 0a` (ช่องสัญญาณ 10)
  * Value Type: `05` (`UINT16`)
  * Value: `01 c2` (ค่า 450)

เซิร์ฟเวอร์ได้รับเฟรม ยืนยันว่า Session อยู่ในสถานะ `ACTIVE` และกระจายข้อมูลไปยัง Event Listener ของแอปพลิเคชัน

---

### ขั้นตอนที่ 5: เซิร์ฟเวอร์ส่งคำสั่ง COMMAND ไปยังอุปกรณ์

แอปพลิเคชันสั่งให้อุปกรณ์เปิดสวิตช์รีเลย์บน Channel `2` ด้วยค่าบูลีน `true`:

```text
05 00 00 08 00 00 00 01 00 02 01 01
```

* **Header (4 ไบต์):** Type `05` (`COMMAND`), Flags `00`, Length `00 08` (8 ไบต์)
* **Payload (8 ไบต์):**
  * Command ID: `00 00 00 01` (รหัสคำสั่ง `1`)
  * Channel: `00 02` (ช่องสัญญาณ 2)
  * Value Type: `01` (`BOOL`)
  * Value: `01` (`true`)

---

### ขั้นตอนที่ 6: อุปกรณ์ยืนยันผลการทำงานด้วย ACK

อุปกรณ์สั่งงานขาควบคุมรีเลย์ทางกายภาพเสร็จสิ้น แล้วตอบกลับด้วยสถานะ `OK` (0):

```text
06 00 00 05 00 00 00 01 00
```

* **Header (4 ไบต์):** Type `06` (`ACK`), Flags `00`, Length `00 05` (5 ไบต์)
* **Payload (5 ไบต์):**
  * Command ID: `00 00 00 01` (รหัสคำสั่ง `1`)
  * Status: `00` (`OK`)

---

### ขั้นตอนที่ 7 & 8: การตรวจเช็คสถานะการเชื่อมต่อ (Heartbeat)

Client ส่งแพ็กเก็ต `PING` พร้อม Nonce `0xCAFEBABE`:

```text
07 00 00 04 ca fe ba be
```

เซิร์ฟเวอร์ตอบรับทันทีด้วยแพ็กเก็ต `PONG` ที่มีค่า Nonce ตรงกัน:

```text
08 00 00 04 ca fe ba be
```

---

### ขั้นตอนที่ 9 & 10: การปิดการเชื่อมต่ออย่างเป็นระเบียบ (Clean Teardown)

อุปกรณ์เตรียมเข้าสู่โหมดประหยัดพลังงาน จึงส่งแพ็กเก็ต `DISCONNECT` พร้อมรหัส `0`:

```text
0a 00 00 02 00 00
```

* **Header (4 ไบต์):** Type `0a` (`DISCONNECT`), Flags `00`, Length `00 02` (2 ไบต์)
* **Payload (2 ไบต์):** Code `00 00` (`0` คือปิดตามปกติ)

เซิร์ฟเวอร์เปลี่ยนสถานะเป็น `CLOSED` ลบข้อมูลการลงทะเบียนอุปกรณ์ในระบบ และสั่งปิด Socket การเชื่อมต่ออย่างเรียบร้อย
