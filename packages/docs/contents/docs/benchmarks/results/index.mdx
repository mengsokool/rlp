# Capacity & Benchmark Results

This document presents empirical capacity, throughput, and resource utilization measurements for `@raina-iot/rlp` on Node.js.

---

## Test Environment

- **Host Machine:** Apple Silicon (macOS arm64, 8 logical CPUs, 16 GiB RAM).
- **Runtime:** Node.js v24.18.0.
- **Topology:** Single-host loopback over plain TCP.
- **Methodology:** The RLP server ran as an isolated child process; the synthetic device generator ran in the parent process. Both processes independently recorded RSS, V8 heap usage, CPU deltas, and event loop latency once per second.

---

## 1. Connection Scaling Ramp

Snapshots taken during connection ramp tests before load generation:

| Connected Devices | Server RSS | Server Heap Used | Event Loop p99 | Disconnects |
|---:|---:|---:|---:|---:|
| **1,000** | 73.6 MiB | 9.1 MiB | 2.29 ms | 0 |
| **5,000** | 99.3 MiB | 26.3 MiB | 1.21 ms | 0 |
| **10,000** | 121.7 MiB | 32.0 MiB | 1.23 ms | 0 |

## 2. 10-Minute Sustained Telemetry Confirmation

A sustained 10-minute confirmation run was executed with 10,000 concurrent authenticated devices transmitting regular environmental sensor updates:

| Scenario | Connections | Rate | Duration | Server RSS | Event Loop p99 | Result |
|---|---:|---:|---:|---:|---:|---|
| **Environmental Telemetry** | 10,000 | 1,994.85 msg/s | 10 minutes | 90.8 MiB | 1.99 ms | **PASS** |

### Key Observations

* **Zero Frame Loss:** The device generator wrote `1,192,918` frames, and the server received `1,192,823` frames (the delta of 95 frames represents in-flight network transit at time of snapshot).
* **Fault-Free Execution:** 0 unexpected disconnections, 0 protocol errors, 0 simulator errors, and 0 socket backpressure events.
* **Low CPU Footprint:** The server consumed an average of **8.48% of one CPU core** (user + system time combined).
* **Minimal Event Loop Latency:**
  * Median (p50): **1.29 ms**
  * 95th Percentile (p95): **1.52 ms**
  * 99th Percentile (p99): **1.99 ms**
* **Compact Memory Footprint:** Final server heap used was **30.6 MiB** (heap total 32.6 MiB) with an overall process RSS of **90.8 MiB**.

---

## 3. Command & ACK Performance

In a command dispatch test with 1,000 active devices receiving 1,000 commands/sec over 15 seconds:
* The server dispatched and acknowledged **11,225 commands**.
* **ACK Latency Distribution:**
  * p50: **0.153 ms**
  * p95: **0.786 ms**
  * p99: **1.567 ms**
* Zero dropped commands, zero socket backpressure events, and zero disconnects were observed.

---

## 4. Fragmentation & Stream Stress

The incremental decoder was subjected to aggressive fragmentation stress testing:
* **Chunk Fragmentation:** 1,000 devices transmitting sensor frames chopped into random 1–64 byte fragments for 15 seconds: 0 errors, 0 dropped frames.
* **Byte-at-a-Time:** 100 devices transmitting byte-by-byte for 15 seconds: 0 errors, exact sample counts decoded.

---

## 5. Conclusions and Limits

These measurements establish a proven lower bound: a single Node.js process using `@raina-iot/rlp` can comfortably sustain **10,000 active devices** at **2,000 telemetry messages/second** while consuming **under 100 MiB of RAM** and less than **10% of a single CPU core**.

> **Note:** At 25,000 requested connections on a single machine, OS ephemeral port exhaustion (`EADDRNOTAVAIL`) occurred on the localhost generator before server saturation was observed.
