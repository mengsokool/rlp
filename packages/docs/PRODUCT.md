# Product

## Register

brand

## Users

docs.beenut serves computer-vision developers and technical operators who need to turn custom YOLO ONNX models into usable macOS and Linux vision apps. They are usually trying to install BeeNut, add a model, configure labels and runtime behavior, deploy it, or debug common detection and camera issues.

## Product Purpose

The documentation should make BeeNut feel practical, trustworthy, and quick to adopt. Success means a developer can understand the runtime, follow the happy path from setup to model configuration, and recover from common failures without needing to reverse-engineer the app.

## Brand Personality

Clear, technical, grounded. The voice should feel like a competent field guide for computer-vision work: direct enough for experienced developers, but structured enough for first-time adopters.

## Anti-references

Avoid generic gray documentation themes that make navigation and active states hard to distinguish. Avoid decorative AI/SaaS styling, low-contrast muted text, and visual noise that distracts from step-by-step technical reading.

## Design Principles

Make the current path obvious.
Use color to separate navigation, actions, code, and callouts.
Keep technical content calm and scannable.
Favor high-contrast reading over subtle elegance.

## Accessibility & Inclusion

Aim for WCAG AA contrast for body text and controls. Keep focus states visible, support dark mode without losing brand recognition, and avoid color-only distinctions for critical states.
